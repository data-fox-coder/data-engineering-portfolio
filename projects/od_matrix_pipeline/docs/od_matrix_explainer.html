Origin-Destination Matrix

Code walkthrough // od_matrix_demo.py

01 // OverviewWhat the script actually does

The script takes raw journey records (one row per trip) and turns them into an origin-destination matrix, a grid showing how many trips happened between every pair of towns.

It follows the same three-stage pattern as the RAWG pipeline:

Bronze
Raw trips
Silver
Cleaned
Gold
OD Matrix
Why this matters Structuring the pipeline in named stages, rather than one long script, mirrors how a real production pipeline would be organised, and it's easy to explain in an interview: each stage has one job.

02 // Bronze LayerSimulating raw trip data

zones = ["Eastbourne", "Brighton",
         "Lewes", "Hastings",
         "Seaford", "Uckfield"]

raw_trips = pd.DataFrame({
    "origin": np.random.choice(
        zones, size=2500),
    "destination": np.random.choice(
        zones, size=2500),
})

np.random.choice picks a random town for each trip's origin and destination, 2,500 times. This builds a table that looks like real trip-level data, one row per journey.

A fixed random.seed(42) is set earlier in the script, so the "random" data is actually identical every time you run it, useful for a reproducible demo.

Design choice Brighton is deliberately boosted as a destination afterwards, to mimic a real commuter hub rather than pure noise, so the resulting matrix has a believable pattern to talk through.

03 // Silver LayerCleaning the data

silver_trips = raw_trips[
    raw_trips["origin"]
    != raw_trips["destination"]
].copy()

This line filters out any "trip" where the origin and destination are the same town. Those rows don't add anything meaningful to an OD matrix, so they're removed here, before the matrix is built.

Why this matters In a real pipeline, this stage would also handle nulls, duplicate ticket scans, and invalid zone codes. Even a simple rule like this shows you're thinking about data validation as a distinct step, not skipping straight to the output.

04 // Gold LayerBuilding the matrix

Step 1, build every possible town-pair combination, even ones with zero trips:

full_index = pd.MultiIndex.from_product(
    [zones, zones],
    names=["origin", "destination"]
)

This creates a complete list of every origin paired with every destination, 36 pairs for 6 towns, before any real data is added.

Step 2, count actual trips per pair, then slot them onto that full grid:

trip_counts = (
    silver_trips
    .groupby(["origin", "destination"])
    .size()
)

od_long = trip_counts.reindex(
    full_index, fill_value=0
).reset_index()

.reindex(full_index, fill_value=0) is the key line. Any pair with no recorded trips gets a 0 instead of being left out entirely.

Step 3, reshape into an actual matrix:

od_matrix = od_long.pivot(
    index="origin",
    columns="destination",
    values="trips"
)

.pivot() turns the long list of pairs into a proper grid, origins down the side, destinations across the top, exactly the shape needed for a Power BI matrix visual.

Interview talking point This zero-fill step is the single most important design decision in the whole script. Without it, "no trips between two towns" and "we have no data for this pair" would look identical, and that's a real reporting bug in OD matrices.

05 // VisualisationDrawing the heatmap

fig, ax = plt.subplots(figsize=(8, 6))
im = ax.imshow(
    od_matrix.values, cmap="viridis"
)

ax.imshow() renders the matrix as a grid of coloured cells, darker or lighter depending on trip count. It's the fastest way to turn a numeric matrix into something visually scannable.

for i in range(len(zones)):
    for j in range(len(zones)):
        value = od_matrix.values[i, j]
        ax.text(j, i, int(value),
                ha="center", va="center")

This nested loop writes the actual trip count as text inside each cell, so the heatmap is readable as data, not just colour.

One bug worth mentioning The first run failed on np.fill_diagonal() because pandas returned a read-only array after the pivot. Fixed with .to_numpy(copy=True) to force a writable copy. A small, honest debugging story like this lands well in interview.

06 // Check YourselfQuick recap quiz

1. Why use MultiIndex.from_product before counting trips?

Correct answer: option 2. Building the full grid first means .reindex() can fill in 0 for any pair with no recorded trips, rather than leaving a gap.

2. What does .pivot() do in the gold layer step?

Correct answer: option 3. It turns rows of (origin, destination, count) into a proper origin-by-destination grid.

3. Why were intra-zone trips removed at the silver layer?

Correct answer: option 1. A "trip" from a town to itself doesn't represent a flow, so it's filtered out as a validation rule.
